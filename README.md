# MusicSensor — Beta 6（音声回答・実機確認版）

音を聴いて、ドレミやコード名を声またはボタンで答える個人用トレーニング。ベータ6で日本語の音声回答と、同意した場合だけの未回答音声保存を追加しました。インカム対応・Web公開は後のベータです。

## 起動

Node.js **24.19.0**（24系LTS）とnpmを使います。Python・Condaは不要です。nvm導入済みならプロジェクトで `nvm install` → `nvm use` が使えます。

取得済みのWSL作業ディレクトリで：

```bash
git fetch origin
git switch beta-6
git pull --ff-only origin beta-6
nvm use
npm ci
npm run dev
```

ターミナルに表示されるLocalアドレスをPCブラウザで開きます。WSLではWindows側のブラウザを使えます。終了は `Ctrl+C`、再開は `npm run dev`。作業場所の候補は `~/AppDev/MusicMaster` または `~/AppDev/MusicSensor` です。

初めて取得する場合は `git clone --branch beta-6 https://github.com/whiterockshi/MusicMaster.git` を使い、取得先のディレクトリへ移動してから `npm ci` → `npm run dev` を実行してください。既存ファイルを上書きしないでください。

## 音声回答の始め方

1. PCのlocalhostで起動し、室内・停車中に「サポート」→「設定」を開きます。
2. 「音声回答（日本語）」を選び、マイクと認識サービスについての説明に同意します。この選択だけではマイクを起動しません。
3. まず「音声入力をテスト」を押し、ブラウザのマイク許可を与え、「ド」などを話してください。認識テキストと判定候補を確認できます。テストは15秒以内で終了し、テスト音声は保存しません。
4. ステージを開始します。音声モードは出題・次問を自動進行し、合図が終わってからマイクを受け付けます。認識結果が有効な候補になれば自動採点します。自動進行は設定でOFFにでき、ボタンも併用できます。
5. 一時停止・画面非表示・退出でマイクを停止します。権限拒否・通信エラー時は採点せず停止し、ボタン回答で同じ問題から再開できます。

| レベル | 発話例 |
| --- | --- |
| Lv1 | 「ド」「ファシャープ」「シフラット」 |
| Lv2 | 「ド レ」（まとめて話すのがおすすめ）。別々の場合は1音目の表示を確認してから2音目を話す |
| Lv3 | 「ド メジャーセブン」「レ マイナーセブン」「ソ セブン」「シ マイナーセブン フラットファイブ」 |

M7とm7は「メジャーセブン」「マイナーセブン」と明確に区別してください。「エムセブン」だけでは判定しません。雑音・対象外の発話・候補が割れた結果は無理に採点せず、時間内に話し直せます。音声認識の結果を正答に寄せる補正はしません。

### 音声の処理先と対応環境

ブラウザ標準のSpeechRecognition／webkitSpeechRecognitionを使います。音声がApple/Google等のOS・ブラウザ提供元サービスへ送られる場合があり、実際の処理先・通信要否はブラウザに依存します。端末内処理やオフライン動作は保証できません。アプリ独自の認識サーバー、有料AI API、APIキーは使いません。マイク・録音にはアプリ内の事前同意とブラウザの許可が必要です。カメラは利用しません。

PCのlocalhostまたはHTTPSで試してください。**iPhoneからWSLのLAN HTTPアドレスへ接続しても音声入力は使えません。** iPhoneには別途HTTPSのテスト経路が必要です。今回、外部公開はしていません。ブラウザの対応状況、音声認識サービス設定、マイク接続や通信状況によって使えない場合はボタン回答を利用できます。

**iPhoneから開く具体的な手順は [iPhone Safari用ローカルHTTPS設定](docs/IPHONE_HTTPS.md) を参照してください。** 証明書とWindowsの接続設定を用意した後、`npm run dev:https` で起動できます。設定画面にも接続状況と手順の案内を表示します。HTTPSへ移ると保存領域が変わるため、先にJSONバックアップを保存してください。

自動テストでは認識イベント・録音機能を模擬しています。実マイクの精度、iPhone SE/指定iOSのSafari、録音と認識の同時利用は**実機確認待ち**です。まず音声入力テストで「ド」「レフラット」「ドマイナーセブン」を試し、次に各レベルを1回プレイしてください。発話・認識テキスト・ブラウザ/OS・エラー表示を添えてフィードバックをお願いします。走行中のテストは行わないでください。

### 未回答音声の保存（任意）

録音は初期OFF。「未回答時の音声を端末内に保存する」で別の同意をした場合だけ、回答受付中の音声を一時録音します。完全未回答の最新2件を各10秒・1MiBまでIndexedDBへ保存し、3件目は最古のメタデータと音声を削除します。回答成立・部分回答・一時停止では音声を残しません。サイズ超過や録音未対応時は音声を破棄し、メタデータだけ保存します。

サポートで音声を再生・個別ダウンロードできます。録音は**JSONバックアップには含まれません**。JSON復元では古い録音を削除し、別の履歴の音声と混同しないようにします。復元した同意フラグは信用せず、入力はボタン・録音OFFへ戻すため、音声利用は設定から改めて同意してください。録音は自動送信しません。Codexに共有する場合も、ユーザーが内容を確認して手動で渡してください。

## ゲーム

| レベル | 出題 | ボタン回答 | 採点 |
| --- | --- | --- | --- |
| Lv1 | 1音。20問に全12音、各1〜2回 | 音名を選ぶと判定 | 正解5点 |
| Lv2 | 異なる2音を順番に出題。10問 | 1音目・2音目を選び「この回答で判定する」 | 1音正解2点、両音正解5点 |
| Lv3 | 12ルート×M7 / m7 / 7 / m7b5の48種類から5問 | ルート・種類を選び「この回答で判定する」 | 両方正解のみ5点 |

通常セッションはLv1が20問・100点満点、Lv2が10問・50点満点、Lv3が5問・25点満点。回答時間はLv1/3が8秒、Lv2が10秒です。Lv2は1音目・2音目の切り替えボタンで選び直せます。時間切れでも選択済みの音を採点します。「わからない」は選択内容を破棄し、未回答・0点にします。未回答音だけを理由に復習へ追加しません。

Lv3は、ベース音域（E1〜Eb2）からルートを取り、3・5・7度を通常の積み重ねより1オクターブ上げます。CM7なら **C2→E3→G3→B3** の分散発音、短い間、**C2・E3・G3・B3** の同時発音を聞きます。Lv3では音域の選択にかかわらずこの配置を使います。上声は、承認済みのCM7例を優先し、Lowギターの上限で折り返しません。サイン波を使い、和音時は音量を抑えています。

誤答後（Lv2は未選択の音がある場合も）は正誤音→正解音名の案内→2秒待機→元の音列・コードの再生。再生完了後に次問へ進めます。読み上げは端末内の日本語音声がある場合のみで、ない場合は画面と合図で進みます。外部の音声サービスは利用しません。

一時停止から同じ問題を再生できます。画面非表示では一時停止します。再読込では進行中セッションを中断として記録し、続きからの再開はできません。

## 復習・記録・設定

- 復習はレベル・音域・音列の順序・コード種類を区別。全レベルを混ぜてシャッフルし、元の形式・音域で再生します。完全正解で待ち一覧から除去し、誤答履歴は保持します。
- サポート＞設定でシャープ／フラット表記と、Highギター（E3〜Eb4）・Lowギター（E2〜Eb3）・ベース（E1〜Eb2）を選択。次のLv1・Lv2練習に適用します。Lv3は固定配置です。
- 苦手分析はレベル・音域ごとの「リセット後」「全期間」の2グラフ。Lv2は各音を個別集計、Lv3は48コードを個別集計。未回答は分母に含めません。5回答未満はデータ不足です。小さい画面では横スクロールしてください。
- 分析リセットは確認付き。選択したレベル・音域のリセット後集計だけを初期化し、履歴・累計は維持します。
- カレンダーは通常練習だけを表示し、日別一覧は新しい順に最大5件。レベル×音域の9通りの得点グラフは満点を100点に換算し、表示上限と関係なく全完了セッションから集計します。
- サポートでJSONバックアップ・復元（全置換・確認あり）、結果CSV、未回答例の確認・削除・出力ができます。詳細未回答例は最新2件FIFO。録音は別途同意した場合だけ保存します。

## 保存と互換性

ベータ6は録音ストア追加のためIndexedDBをバージョン2へ更新します。**同じブラウザ保存領域でベータ5へ戻すことは未対応**です。更新前にJSONを保存し、旧版との比較は別のブラウザプロファイルで行ってください。

記録は**ブラウザ・プロファイル・アクセス先（ホストとポート）ごと**のIndexedDB（musicsensor → state → main、任意の録音はdebugAudio）に保存します。自動クラウド同期はありません。複数タブの同時プレイは未対応です。

ベータ4の保存データ・JSONをそのまま読み込めます。音域記録がない旧データは旧Highギター（C4〜B4）扱い。旧式の復習は記録されたセッションの音域から仕分け直します。**Lv2/3を保存した後、同じブラウザ保存領域でベータ4へ戻すことは未対応**です。別ブラウザプロファイルを使うか、先にJSONを保管してください。

サポート画面で全データのJSON換算サイズを確認できます。ベータ4の20問の代表例は4,180バイト（約4.1KiB）。ベータ5は音列・コード属性を追加するため増えます。実際のIndexedDBのディスク使用量にはブラウザ側の管理領域も加わります。

履歴は自動削除しません。現在の読み込み検証は最大10,000セッション、JSONインポートは10MiB以下です。長期利用時のアーカイブ・整理機能は未実装。ブラウザデータ削除、端末変更、公開先変更の前にはJSONを保存してください。プライベートブラウズでは保存が維持されない場合があります。

## ボタン回答の動作確認

室内・停車中にPCのスピーカーまたはヘッドホンで確認してください。

1. Lv1が以前と同じように動き、既存の履歴・設定が残っているか。
2. Lv2で2音を順番に聞けるか。1音正解2点・2音正解5点になり、選び直しができるか。
3. Lv3で分散和音→同時和音を聞けるか。ルートと種類を選んで5問完走できるか。
4. 3つの音域とシャープ／フラットで使えるか。誤答後の再発音が出題時と一致するか。
5. 全レベル混在の復習で元の音域・形式が保たれ、完全正解で一覧から消えるか。
6. レベル・音域別の分析と得点グラフが更新されるか。JSONバックアップを保存できるか。

OS・ブラウザ・操作手順・期待結果と実際の結果を添えてフィードバックをください。iPhone実機での音・Bluetooth・Safari動作は未検証です。音声回答の実機確認は下記手順で行ってください。

## 開発者向け

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

クラウドの既存Chromiumを使う場合：

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

このクラウドではPlaywrightのブラウザ配布先がネットワーク制限で拒否されたため、既存の `/usr/bin/chromium` を使用しています。ビルド成果物は `npm run preview` で確認します。`dist/index.html` の直接ダブルクリックでは起動しません。

ベータ4の確定版はGitタグ `v0.4.0`。ベータ6は `beta-6` ブランチで確認できます。詳細は [PLAN.md](PLAN.md)、作業方針は [AGENTS.md](AGENTS.md) を参照してください。

初回案内は端末内日本語音声の読み込みを最大2秒待ちます。日本語音声がない場合は画面に通知するので、OS・ブラウザの日本語読み上げ音声を確認してください。A4＝440Hzを維持しています。新HighギターのGはG3（約196Hz）、旧音域のG4は約392Hzです。旧20問のLv2/3履歴は保持・復元できます。

音域変更後の問題は配置バージョン2、変更前の問題はバージョン1として保存します。旧問題の復習は元の高さと配置で鳴り、一覧には「旧音域の問題」と表示します。累計分析には旧音域の履歴も含まれます。必要なら分析リセットで新しい集計期間を開始してください。新配置のLv3はカレンダー・分析の「ベース」に記録し、Lv3を選ぶとベースが初期選択されます。旧Lv3の他音域の履歴も引き続き選んで見られます。

Lv3は表示上の音名・オクターブを保ち、実際には全音を1オクターブ上で再生します。例：表示B1・D3・F3・A3に対し実音B2・D4・F4・A4。分散・同時・正解確認・復習に共通で、Lv1/2は変更しません。

ベータ5の確定版はGitタグ `v0.5.0` として保持しています。ベータ6は `beta-6` ブランチで実機確認を進めます。

技術資料： [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)。認識エンジンが短い音名を別の語に変換する場合があるため、実機データを見ながら語彙の改善を進めます。
