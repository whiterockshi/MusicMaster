# MusicSensor — Beta 5

音を聴いてボタンで音名・コード名を答える個人用トレーニング。ベータ4のLv1に、2音問題とコード問題を追加しました。音声回答・録音・インカム対応・Web公開はまだ行いません。

## 起動

Node.js **24.19.0**（24系LTS）とnpmを使います。Python・Condaは不要です。nvm導入済みならプロジェクトで `nvm install` → `nvm use` が使えます。

取得済みのWSL作業ディレクトリで：

```bash
git fetch origin
git switch beta-5
git pull --ff-only origin beta-5
nvm use
npm ci
npm run dev
```

ターミナルに表示されるLocalアドレスをPCブラウザで開きます。WSLではWindows側のブラウザを使えます。終了は `Ctrl+C`、再開は `npm run dev`。作業場所の候補は `~/AppDev/MusicMaster` または `~/AppDev/MusicSensor` です。

初めて取得する場合は `git clone --branch beta-5 https://github.com/whiterockshi/MusicMaster.git` を使い、取得先のディレクトリへ移動してから `npm ci` → `npm run dev` を実行してください。既存ファイルを上書きしないでください。

## ゲーム

| レベル | 出題 | ボタン回答 | 採点 |
| --- | --- | --- | --- |
| Lv1 | 1音。20問に全12音、各1〜2回 | 音名を選ぶと判定 | 正解5点 |
| Lv2 | 異なる2音を順番に出題。10問 | 1音目・2音目を選び「この回答で判定する」 | 1音正解2点、両音正解5点 |
| Lv3 | 12ルート×M7 / m7 / 7 / m7b5の48種類から5問 | ルート・種類を選び「この回答で判定する」 | 両方正解のみ5点 |

通常セッションはLv1が20問・100点満点、Lv2が10問・50点満点、Lv3が5問・25点満点。回答時間はLv1/3が8秒、Lv2が10秒です。Lv2は1音目・2音目の切り替えボタンで選び直せます。時間切れでも選択済みの音を採点します。「わからない」は選択内容を破棄し、未回答・0点にします。未回答音だけを理由に復習へ追加しません。

Lv3はルートを最低音にした基本形です。CM7なら **C→E→G→B** の分散発音、短い間、**C・E・G・B** の同時発音を聞きます。音域設定はルートに適用し、上の構成音はそのオクターブを越えます。サイン波を使い、和音時は音量を抑えています。

誤答後（Lv2は未選択の音がある場合も）は正誤音→正解音名の案内→2秒待機→元の音列・コードの再生。再生完了後に次問へ進めます。読み上げは端末内の日本語音声がある場合のみで、ない場合は画面と合図で進みます。外部の音声サービスは利用しません。

一時停止から同じ問題を再生できます。画面非表示では一時停止します。再読込では進行中セッションを中断として記録し、続きからの再開はできません。

## 復習・記録・設定

- 復習はレベル・音域・音列の順序・コード種類を区別。全レベルを混ぜてシャッフルし、元の形式・音域で再生します。完全正解で待ち一覧から除去し、誤答履歴は保持します。
- サポート＞設定でシャープ／フラット表記と、Highギター（C4〜B4）・Lowギター（C3〜B3）・ベース（C2〜B2）を選択。次の通常練習に適用します。
- 苦手分析はレベル・音域ごとの「リセット後」「全期間」の2グラフ。Lv2は各音を個別集計、Lv3は48コードを個別集計。未回答は分母に含めません。5回答未満はデータ不足です。小さい画面では横スクロールしてください。
- 分析リセットは確認付き。選択したレベル・音域のリセット後集計だけを初期化し、履歴・累計は維持します。
- カレンダーは通常練習だけを表示し、日別一覧は新しい順に最大5件。レベル×音域の9通りの得点グラフは満点を100点に換算し、表示上限と関係なく全完了セッションから集計します。
- サポートでJSONバックアップ・復元（全置換・確認あり）、結果CSV、未回答例の確認・削除・出力ができます。詳細未回答例は最新2件FIFOで、ベータ5でも録音はありません。

## 保存と互換性

記録は**ブラウザ・プロファイル・アクセス先（ホストとポート）ごと**のIndexedDB（musicsensor → state → main）に保存します。自動クラウド同期はありません。複数タブの同時プレイは未対応です。

ベータ4の保存データ・JSONをそのまま読み込めます。音域記録がない旧データはHighギター扱い。旧式の復習は記録されたセッションの音域から仕分け直します。**Lv2/3を保存した後、同じブラウザ保存領域でベータ4へ戻すことは未対応**です。別ブラウザプロファイルを使うか、先にJSONを保管してください。

サポート画面で全データのJSON換算サイズを確認できます。ベータ4の20問の代表例は4,180バイト（約4.1KiB）。ベータ5は音列・コード属性を追加するため増えます。実際のIndexedDBのディスク使用量にはブラウザ側の管理領域も加わります。

履歴は自動削除しません。現在の読み込み検証は最大10,000セッション、JSONインポートは10MiB以下です。長期利用時のアーカイブ・整理機能は未実装。ブラウザデータ削除、端末変更、公開先変更の前にはJSONを保存してください。プライベートブラウズでは保存が維持されない場合があります。

## ベータ5の動作確認をお願いします

室内・停車中にPCのスピーカーまたはヘッドホンで確認してください。

1. Lv1が以前と同じように動き、既存の履歴・設定が残っているか。
2. Lv2で2音を順番に聞けるか。1音正解2点・2音正解5点になり、選び直しができるか。
3. Lv3で分散和音→同時和音を聞けるか。ルートと種類を選んで5問完走できるか。
4. 3つの音域とシャープ／フラットで使えるか。誤答後の再発音が出題時と一致するか。
5. 全レベル混在の復習で元の音域・形式が保たれ、完全正解で一覧から消えるか。
6. レベル・音域別の分析と得点グラフが更新されるか。JSONバックアップを保存できるか。

OS・ブラウザ・操作手順・期待結果と実際の結果を添えてフィードバックをください。iPhone実機での音・Bluetooth・Safari動作は未検証です。音声回答はベータ6で別途同意・検証して導入します。

## 開発者向け

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

クラウドの既存Chromiumを使う場合：

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

このクラウドではPlaywrightのブラウザ配布先がネットワーク制限で拒否されたため、既存の `/usr/bin/chromium` を使用しています。ビルド成果物は `npm run preview` で確認します。`dist/index.html` の直接ダブルクリックでは起動しません。

ベータ4の確定版はGitタグ `v0.4.0`。ベータ5は `beta-5` ブランチで確認できます。詳細は [PLAN.md](PLAN.md)、作業方針は [AGENTS.md](AGENTS.md) を参照してください。

初回案内は端末内日本語音声の読み込みを最大2秒待ちます。日本語音声がない場合は画面に通知するので、OS・ブラウザの日本語読み上げ音声を確認してください。HighギターG4の設定周波数は約392Hz、G#4/Ab4は約415.3Hzです。旧20問のLv2/3履歴は保持・復元できます。
